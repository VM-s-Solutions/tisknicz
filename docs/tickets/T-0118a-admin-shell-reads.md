# T-0118a — Admin shell + read surfaces (`/admin/login`, `/dashboard/admin`, orders / faktury / audit)

## Context

T-0118a is the **first of three slices** that the user split T-0118 ("admin dashboard") into at the 2026-06-15 deliberation. The split ships in **two PRs**: **T-0118a alone (PR 1)**, then **T-0118b (order-actions) + T-0118c (ops + control-plane) bundled, risk-ascending b → c (PR 2)**. Each slice is one ticket. **T-0118a is the verification harness for the whole feature**: b and c assert their write effects against the read lists this slice builds (a refund in b must move the order's state on a's `/dashboard/admin/orders` list; an outbox retry in c must clear the stalled-outbox KPI tile on a's overview). It must therefore land first, complete and correct, before any admin write surface is built.

This slice is **read-only + an auth gate**. It does four things: (1) replaces the Phase-1 `(admin)/layout.tsx` skeleton (`return <>{children}</>`) with the **real admin shell** — top/side nav + the admin-session gate; (2) builds the **dedicated `/admin/login`** page on the admin host (per ADR 0013, NOT a reuse of the customer `/login`); (3) builds the **overview** at `/dashboard/admin` with deep-linking KPI tiles; (4) builds the three **read lists** — all-orders, all-invoices, audit-log — each paged, SSR, URL-state-filtered. It satisfies **US-admin-0001** (admin login), **US-admin-0002** (overview), **US-admin-0009 AC-1** (all-orders list + filters; the detail page is slice b), **US-admin-0012 AC-1/AC-2** (all-invoices list + per-row PDF download), and **US-admin-0015 AC-1** (audit-log list + filters; the diff detail is slice c).

The implementation precedent is the shipped **maker order dashboard** (`frontend/src/app/(maker)/dashboard/maker/objednavky/`, T-0087a) and the **maker payout dashboard** (`frontend/src/app/(maker)/dashboard/maker/vyplaty/`, T-0116): Server Component pages, `dynamic = 'force-dynamic'`, URL-state pagination via `searchParams` + `<Link>`, hand-written `Result<T, ApiError>` helpers in `lib/api-client-helpers/` (patterns.md §B.16), mobile-cards/desktop-table responsive layout, `formatCzk(amountMinor, currency)` (`lib/money/formatter.ts`) for money, Czech-short dates via `formatDate` (`lib/utils/dates.ts`), and the `order.state.*` labels/badges from `lib/orders/state-labels.ts`. T-0118a mirrors all of it on the new admin host so the admin dashboard stays structurally identical to the maker dashboard for review and maintenance.

Everything these lists render is **already on the admin NSwag client** — `admin-api.v1.ts` types `adminOrders(page, pageSize, state, country, makerId, customerEmail) → GetAllOrdersResponse`, `adminInvoices(page, pageSize, type, country, recipient, dateFrom, dateTo) → GetAllInvoicesResponse`, `auditLog(page, pageSize, adminUserId, actionCode, targetEntity, dateFrom, dateTo) → GetAdminAuditLogResponse`, with `AdminOrderListItemDto` / `AdminInvoiceListItemDto` / `AdminAuditLogItemDto` item shapes (regenerated by T-0105/0108/0109/0111). **This slice is a read-only consumer of that contract — NO NSwag regen.**

## Locked design decisions

Captured per `docs/process/deliberation.md`. The user locked the split and the auth model at the 2026-06-15 deliberation; the rest is ADR/pattern-locked or PM-absorbed from the maker-dashboard precedents.

### A. User-locked at deliberation (non-negotiable)

1. **Dedicated `/admin/login` on the admin host — NOT a reuse of the customer `/login` (ADR 0013).** Slice a builds a thin admin variant of `LoginForm` that posts `login('admin', { email, password })` (the `login(host, …)` helper already takes the host as its first argument — the existing `LoginForm`'s own doc-comment names `host="admin"` as the intended reuse). The JWT it receives carries `aud=admin`; per-host audience match means a customer/maker token replayed against the admin host 401s at the backend (ADR 0013), and a non-admin who reaches `/admin/login` gets `auth.forbidden` (US-admin-0001 AC-2). The admin-session gate redirects unauthenticated admin routes to **`/admin/login`**, not the customer `/login` (the current `middleware.ts` redirects every audience — including admin — to `/login`; this slice retargets the admin branch to `/admin/login`). **Rejected:** reusing the customer `/login` with a post-login audience switch (mixes audiences on one form, breaks the per-host JWT discipline ADR 0013 exists to enforce, and would let a customer session leak into the admin redirect target); a shared multi-host login picker (over-built for two operators).

2. **Overview KPI tiles, each deep-linking into a read list or action surface (US-admin-0002).** The overview renders four tile groups: **order counts by state** (deep-link → `/dashboard/admin/orders?state=…`), **pending payouts** (`Processing` batches → the payout surface, built in slice c — forward-compat link), **stalled-outbox count** (→ the outbox surface, slice c — forward-compat link), and **recent disputes** (→ the orders list filtered to disputed / the dispute surface in slice b). Counts come from the **existing** T-0111 / T-0109 / T-0106 / T-0102 reads. **If a specific count is not exposed by an existing read endpoint, a thin count-endpoint follow-up ticket is logged and the tile renders a graceful "—" placeholder — NO backend is added in this frontend bundle.** **Rejected:** adding count-aggregation endpoints inside this frontend slice (this is a frontend-only bundle; backend counts are a separate, logged follow-up); computing counts client-side by over-fetching full lists (unpaginated over-fetch, business-adjacent aggregation in the frontend).

3. **Type-to-confirm is RESERVED exclusively for `DeleteUserPermanently` (slice c).** This slice introduces **no** type-to-confirm affordance anywhere — it is read-only. Recorded here so the harness's reviewers know the pattern's single home is slice c's GDPR-delete screen, and no read surface borrows it.

### B. ADR + pattern-locked (no relitigation)

- **patterns.md §B.1 — Server Components by default.** The shell, overview, and all three lists are fully server-rendered. The **only** client island in this slice is the `/admin/login` form (`'use client'`, event-handler `login(...)`) and the per-row invoice **download button** (event-handler blob fetch — §C). Everything else is `<Link>` navigation, zero shipped JS.
- **patterns.md §B.4 + §B.16 — all data via `apiFetch` + a hand-written helper.** A new `lib/api-client-helpers/admin-client.ts` wraps `adminApi.adminOrders/adminInvoices/auditLog(...)` and returns `Result<T, ApiError>`. No raw `fetch`, no `useEffect` data fetching anywhere in the route. Naming follows the `orders-client.ts` / `payouts-client.ts` convention.
- **patterns.md §B.14 + ADR 0024 — SSR auth cookie forwarding.** The Server Component renders forward the **admin-audience** cookie (`accessCookieName('admin')`) to the admin host. A customer/maker JWT replayed against the admin host 401s at the backend (ADR 0013); the frontend adds no parallel auth logic. The `Unscoped()` IDOR scope is a backend concern (the admin endpoints already query all-makers/all-customers); the frontend passes no scoping id.
- **ADR 0022 — NSwag is the contract.** `frontend/src/lib/api-client/admin-api.v1.ts` is consumed, never hand-edited (pre-commit hook). The admin client was **already regenerated by T-0105/0108/0109/0111**; T-0118a consumes the existing `adminOrders` / `adminInvoices` / `auditLog` methods. **No backend change and no regen in this slice.**
- **patterns.md §B.8 — URL-state pagination + filters via `searchParams` + `<Link>`.** Every list's page, pageSize, and filters live in the URL; back/forward and deep links round-trip (T-0087a / T-0116 precedent). `page=1` dropped from canonical URLs.
- **patterns.md §B.5 + §B.18 — Czech-only UI via i18n keys.** Zero hardcoded Czech outside `lib/i18n/cs-CZ.ts`. New keys under `dashboard.admin.*`. **The T8 i18n-parity CI gate is LIVE** — a missing key fails CI; every new admin string is keyed before merge.
- **patterns.md §B.10 — `formatCzk(amountMinor, currency)`** for every money figure (order total, invoice total). No arithmetic on the client.
- **Blob download via `apiFetch` `parse: 'blob'`** + `triggerBlobDownload` (the maker `order-actions.tsx` / `fee-invoice-download.tsx` mechanism) — **never** the NSwag `Promise<void>` file method (it discards the PDF body). See §C and the open verification note on the admin invoice-download endpoint.
- **No business logic client-side.** Tile→filter routing, state→badge mapping, and param clamping are presentation/UX only; the backend is authoritative and would 400 a forced out-of-range request.

### C. PM-absorbed (no user input needed)

- **Admin tone = vykání (V form).** All admin-facing strings are written in vykání — admins are operators of JVM YORE, addressed formally. This differs from the maker dashboard's (pending) tykání. Keyed under `dashboard.admin.*`; **every string keyed (T8 gate live)**.
- **All surfaces SSR + `force-dynamic` + URL-state pagination** (T-0087a / T-0116 precedent). The dashboard reflects fresh mutations (slices b/c write; the admin navigates back and the list re-renders server-side). No client polling, no client cache.
- **Admin shell nav** — top-bar/sidebar with the **read** sections live now: **Přehled** (`/dashboard/admin`), **Objednávky** (`/dashboard/admin/orders`), **Faktury** (`/dashboard/admin/faktury`), **Audit log** (`/dashboard/admin/audit`). The b/c sections (payouts, outbox, makers, country config, users) are rendered as **forward-compat nav entries pointing at not-yet-built routes ONLY if disabled/visibly-pending**, otherwise omitted until their slice ships — implementer picks one approach and is consistent; a dead link that 404s is not acceptable. Active-section styling + `aria-current`. A **logout** entry (US-admin-0017, same shape as US-customer-0020) and the admin's email/identity sit in the shell header.
- **Admin-session gate in the shell.** The `(admin)/layout.tsx` reads the admin session (admin-audience cookie) server-side; **no admin session → redirect to `/admin/login?redirect=…`** (open-redirect-guarded path-only target, the `LoginForm` guard precedent). This complements the edge `middleware.ts` (which this slice retargets from `/login` to `/admin/login` for the admin branch) — defense in depth, not a replacement.
- **`/admin/login` is a thin variant of `LoginForm`.** Same `Card` + `Input` + `Button` + `Alert` primitives; posts `login('admin', …)`; on success `router.push(redirectTo)` (path-only guard); maps `auth.invalidCredentials` / `auth.locked` / `auth.forbidden` / `auth.oauthNotAllowedForAdmin` to keyed messages. **No "register" / "magic link" / OAuth links** (admins are provisioned, not self-registered — US-admin-0001: no OAuth). Lives at `app/(admin)/admin/login/` (outside the session gate so it's reachable unauthenticated) or a sibling route group — implementer places it so the gate does not loop it back to itself.
- **Overview KPI tiles render counts from existing reads** (A.2). Each tile is a server-rendered `<Link>` card: label (keyed) + count + deep-link target. A red banner surfaces a stalled outbox (US-admin-0002 AC-2: >10 unrecoverable OR lag > 5 min) **iff** the source read exposes that signal; otherwise the banner condition is logged as part of the count-endpoint follow-up. Tiles whose count is unavailable render "—" and link to the underlying list (where the admin sees the real rows).
- **All-orders list (`/dashboard/admin/orders`)** — `adminOrders(...)`; columns from `AdminOrderListItemDto`: order number, `createdAt` (Czech short), `state` badge (`order.state.*` keys), `makerName`, `customerEmail`, `countryCode`, total via `formatCzk(totalAmountMinor, currency)`. **Admin sees `customerEmail`** — the admin order DTO carries it (unlike the maker DTO's GDPR contact-name-only lock); this is intentional and operator-only. Filters: `state` (mapped to `OrderState` enum), `country`, `makerId`, `customerEmail`, date range (the generated method takes `state/country/makerId/customerEmail`; date-range params are passed iff the generated signature accepts them — implementer verifies, omits cleanly otherwise and logs the gap). Sorted `CreatedAt DESC` (server). Each row → a **forward-compat detail link** `/dashboard/admin/orders/{orderId}` (the detail page is **slice b** — the link target may 404 until b ships; render it disabled/pending or note in the test plan, do not ship a live dead link).
- **All-invoices list (`/dashboard/admin/faktury`)** — `adminInvoices(...)`; columns from `AdminInvoiceListItemDto`: invoice number, `type`, `countryCode`, `recipientName`, total via `formatCzk(totalMinor, currency)`, `createdAt`. Filters: `type`, `country`, `recipient`, date range (all on the generated signature). Each row has a **"Stáhnout fakturu" PDF download** (US-admin-0012 AC-2) via the **blob helper** (`apiFetch` `parse:'blob'` + `triggerBlobDownload`, named `faktura-{invoiceNumber}.pdf`). **Open verification (§ Technical notes): the admin invoice-download endpoint is NOT present on the current `admin-api.v1.ts`** (only the payout `csv(id)` exists). The implementer verifies whether T-0088's invoice-streaming endpoint is exposed on the admin host; if absent, the download button is logged as a thin backend follow-up and rendered disabled-with-tooltip, **NOT** wired to a non-existent path. Sorted `IssueDate DESC` (server).
- **Audit-log list (`/dashboard/admin/audit`)** — `auditLog(...)`; columns from `AdminAuditLogItemDto`: `createdAt` (Czech short + time via `formatDateTime`), `adminUserId`, `actionCode`, `targetEntity`, `targetId`, `notes`. Filters: `adminUserId`, `actionCode`, `targetEntity`, date range (all on the generated signature). Sorted `created_at DESC` (server). Each row → a **forward-compat diff-detail link** `/dashboard/admin/audit/{id}` (the side-by-side `before_json`/`after_json` diff is **slice c**, US-admin-0015 AC-2 — link disabled/pending until c).
- **Filter UI** — server-rendered `<form method="get">` filter bars that write the `searchParams` (no client state); a "Vymazat filtry" reset link. Mirrors nothing on the maker side (which had no filters) but follows the same URL-state discipline.
- **Mobile cards / desktop table** — single server-rendered markup with responsive Tailwind (cards `< md`, grid table `≥ md`), verified at 375/768/1280. No table library.
- **Empty + error + loading states per list** — informational empty (`dashboard.admin.{orders,invoices,audit}.empty.*`), `Alert variant="error"` + retry on API failure, `loading.tsx` pulse skeletons (the `objednavky` / `vyplaty` precedent).
- **Pagination** — local copy of the `objednavky`/`vyplaty` `Pagination` component pointed at each admin base path; `page` clamped (≥ 1) via the `parsePositiveInt` precedent; `pageSize` clamped to the backend cap. `page=1` dropped from canonical URLs.

## Alternatives Considered

- **Option A — Reuse the customer `/login` for admins with a post-login audience switch.** *Rejected per A.1* — mixes audiences on one form and breaks the per-host JWT discipline ADR 0013 exists to enforce; a customer session could leak into the admin redirect. The dedicated `/admin/login` posting `login('admin', …)` keeps the audience boundary clean at the form.
- **Option B — Compute overview counts client-side by fetching full lists.** *Rejected per A.2* — unpaginated over-fetch and business-adjacent aggregation in the frontend; counts come from existing reads, and any missing count is a logged backend follow-up, not a client workaround.
- **Option C — Add count-aggregation endpoints inside this frontend slice.** *Rejected per A.2* — this is a frontend-only bundle; adding backend here violates the slice boundary. Missing counts render "—" and the tile still deep-links to the real list.
- **Option D — Fold the order/invoice/audit detail pages into this slice.** *Rejected* — order detail + actions is slice b; audit diff detail is slice c. Folding them re-merges the very split the user locked and would put write surfaces in the read harness. Rows carry forward-compat links that light up when b/c ship.
- **Option E — Wire the invoice "Stáhnout fakturu" button to a guessed endpoint path.** *Rejected* — the admin invoice-download endpoint is **not on the current contract** (only the payout `csv(id)` exists). Inventing a path would ship a silently-broken download (or, with a generated `Promise<void>` file method, a download that discards the PDF — the `label()` gap). The button is rendered disabled-with-tooltip and the endpoint logged as a backend follow-up.
- **Option F — A generic shared `AdminList` mega-component parameterized for orders/invoices/audit.** *Rejected* — the three lists have different columns, filters, and row links (and one has a download island); a parameterized component couples surfaces that share conventions but not shape. Mirror the conventions, don't share the code (T-0087a Option G / T-0116 Option H precedent).
- **Option G — Client-side filter state (`useState`) instead of URL `searchParams`.** *Rejected per §B.8* — loses deep-linking, back/forward, and refresh-survival, and turns three server lists into client components for zero gain. Filters are a server `<form method="get">` writing the URL.
- **Option H — Ship the b/c nav sections as live links now.** *Rejected per §C* — a nav link to a not-yet-built route 404s. Forward-compat entries are disabled/visibly-pending or omitted until their slice ships; no live dead link.

## Out of scope

- **Order detail page + admin actions** (refund modal, manual state-change with mandatory reason, inline dispute-resolve form) — **T-0118b**. This slice's order rows link forward to that detail page.
- **Ops + control plane** (payout management view/complete/CSV, outbox retry/acknowledge, maker verify/deactivate/ARES-refresh, country config edit with retype-confirm, `DeleteUserPermanently` type-to-confirm screen, audit-log diff detail) — **T-0118c**.
- **Type-to-confirm anywhere** — reserved exclusively for slice c's GDPR-delete screen (A.3); this read-only slice introduces none.
- **Any admin write / mutation** — this slice issues only GET reads + the auth-gate redirect + the (conditional) invoice blob download. No `refund`/`state`/`resolve`/`complete`/`retry`/`erase` calls.
- **Count-aggregation backend endpoints** — if a KPI count isn't exposed by an existing read, it's a logged frontend-bundle-external follow-up; no backend here (A.2 / Option C).
- **Admin invoice-download backend endpoint** — if confirmed absent from the contract, logged as a backend follow-up; the button ships disabled, not wired to a guess (Option E).
- **Full maker/customer sidebar parity** — the maker/customer layouts stay Phase-1 skeletons; this slice builds only the **admin** shell.
- **401 → refresh → retry in `api-fetch.ts`** — known platform gap; unauthenticated SSR falls back to the shell gate's redirect-to-`/admin/login`. Not this slice.
- **Dependency-gap note:** T-0118's INDEX `depends_on` listed T-0102 but **omitted T-0110 + T-0103**; those are added to **T-0118c** (the slice that consumes payout-complete + outbox), and flagged in the grooming commit. T-0118a's own deps are the read-contract tickets T-0105/0108/0109/0111.

## Acceptance criteria

- **AC-1** Given an unauthenticated request to any `/dashboard/admin/*` route, when it is made, then the request is redirected to **`/admin/login`** (not the customer `/login`) with a path-only `redirect` param — enforced by both the retargeted `middleware.ts` admin branch and the shell's server-side session gate (defense in depth).
- **AC-2** Given an admin submits correct credentials on `/admin/login`, when login succeeds, then `login('admin', …)` is called (per-host audience, ADR 0013), the admin session cookie is set, and `router.push` lands on the guarded `redirect` target (path-only). Given a non-admin's credentials, the form shows the keyed `auth.forbidden` message and no admin session is created. The form has **no** register / magic-link / OAuth affordance.
- **AC-3** Given an authenticated admin, when any `/dashboard/admin/*` page renders, then the real shell is present: nav with Přehled / Objednávky / Faktury / Audit log (active section `aria-current`), admin identity + logout in the header, and **no live nav link to a not-yet-built b/c route** (forward-compat entries are disabled/pending or omitted). The shell, overview, and all three lists are Server Components (`dynamic = 'force-dynamic'`); no `useEffect` data fetching exists anywhere in the route group.
- **AC-4** Given the admin lands on `/dashboard/admin`, when the overview renders, then KPI tiles show order counts by state, pending (`Processing`) payouts, stalled-outbox count, and recent disputes — each tile a `<Link>` deep-linking to its read list / forward-compat action surface. A count not exposed by an existing read renders "—" (graceful, no crash) and still links to the underlying list; the stalled-outbox red banner surfaces only when the source read exposes the stalled signal.
- **AC-5** Given the all-orders list at `/dashboard/admin/orders`, when it renders, then a paginated SSR list (sorted `CreatedAt DESC`) shows per row: order number, `createdAt` (Czech short), `state` badge (`order.state.*` keys), `makerName`, `customerEmail`, `countryCode`, total via `formatCzk(totalAmountMinor, currency)`. Filters (state / country / maker / customerEmail / date) are URL-state via a server `<form method="get">`; each row links forward to `/dashboard/admin/orders/{orderId}` (slice b — not a live dead link).
- **AC-6** Given `?state=Paid&country=CZ&page=2`, when the orders list renders, then `getAdminOrders` is called with those filters + page 2, the values round-trip on back/forward and deep links, and junk params (`page=0`, `page=abc`, unknown `state`) clamp/drop to defaults without an error page (backend Validator authoritative). `page=1` is absent from canonical URLs.
- **AC-7** Given the all-invoices list at `/dashboard/admin/faktury`, when it renders, then a paginated SSR list (sorted `IssueDate DESC`) shows per row: invoice number, `type`, `countryCode`, `recipientName`, total via `formatCzk(totalMinor, currency)`, `createdAt`; filters (type / country / recipient / date) are URL-state. Given the admin invoice-download endpoint **exists** on the contract, "Stáhnout fakturu" downloads `faktura-{invoiceNumber}.pdf` via the blob helper (`apiFetch` `parse:'blob'`, NOT a generated `Promise<void>` file method); given it is **absent**, the button renders disabled-with-tooltip and the gap is logged — no wiring to a guessed path.
- **AC-8** Given the audit-log list at `/dashboard/admin/audit`, when it renders, then a paginated SSR list (sorted `created_at DESC`) shows per row: `createdAt` (Czech short + time), `adminUserId`, `actionCode`, `targetEntity`, `targetId`, `notes`; filters (adminUser / actionCode / targetEntity / date) are URL-state; each row links forward to `/dashboard/admin/audit/{id}` (the diff detail is slice c).

## Technical notes

### Why this slice is the verification harness

T-0118b and T-0118c are write slices: a refund moves money and an order state, an outbox retry clears a stalled event, a payout-complete flips a batch to `Vyplaceno`, a GDPR delete anonymizes orders. Each of those effects is **observable on a read list this slice builds** — the orders list, the overview KPIs, the audit log. Building the reads first means b/c each have a ground-truth surface to assert against during their own QA, and the admin (two operators) can already see platform state before any write button exists. Shipping a alone in PR 1 also keeps the high-risk money/PII surfaces (b/c) out of the first admin PR — they land together, risk-ascending, in PR 2.

### Why the dedicated `/admin/login` (and the middleware retarget)

ADR 0013 enforces per-host JWT audience: a customer token cannot be replayed against the admin host. The login form is where the audience is chosen — `login('admin', …)` requests an `aud=admin` token. Reusing the customer `/login` would either issue a customer token (useless against the admin host) or smuggle an audience switch into a shared form (the exact coupling ADR 0013 forbids). The current `middleware.ts` redirects **every** unauthenticated audience — including admin — to `/login`; this slice retargets only the admin branch to `/admin/login`, so an unauthenticated admin lands on the form that issues the right token. The shell's server-side gate is a second layer (the middleware is presence-only until T-0027 validates signatures).

### Why the admin sees `customerEmail` (and the maker doesn't)

`AdminOrderListItemDto` carries `customerEmail`; `MakerOrderListItemDto` carries only `CustomerContactName` (T-0081's compile-time GDPR lock — the maker never sees customer email). The admin is the operator of record and resolves disputes/refunds that require contacting the customer, so the admin order DTO deliberately exposes the email. This slice renders it on the orders list as designed — it is not a GDPR leak, it is the operator surface the maker lock exists to keep *out of the maker's* view.

### The admin invoice-download endpoint gap (verify at impl time)

`admin-api.v1.ts` exposes `csv(id): Promise<void>` (the **payout** bank-file CSV — slice c, operator-only) but **no admin invoice-PDF-download method**. US-admin-0012 AC-2 ("Stáhnout fakturu" streams the PDF) needs such an endpoint on the admin host (T-0088 built the maker/customer invoice-streaming; whether it's exposed on the admin host with `IInvoiceRepository.Unscoped()` is unverified). The implementer **verifies against the running contract**: if present, wire the blob helper (`parse:'blob'` + `triggerBlobDownload`, never the generated `Promise<void>` file method which discards the body); if absent, render the button disabled-with-tooltip and **log a thin backend follow-up ticket** — do not invent a path. AC-7 pins both branches.

### Why every count is from an existing read (no new backend)

The overview's value is at-a-glance triage, but this is a frontend-only bundle. The order-by-state counts, `Processing`-payout count, stalled-outbox count, and recent-disputes feed all have an existing read behind them (T-0111/T-0109/T-0106/T-0102). Where a *count* isn't directly exposed (e.g. the read returns a page, not a total-by-state), the tile shows "—" and deep-links to the list where the admin sees the real rows, and a thin count-endpoint follow-up is logged. Adding count endpoints here would smuggle backend into a frontend slice — A.2 / Option C close that door.

## Risk / mitigation

- **Middleware retarget breaks customer/maker redirect.** *Mitigation:* only the `audience === 'admin'` branch's redirect target changes (`/login` → `/admin/login`); customer/maker branches untouched. AC-1 pins the admin redirect; a regression test on the customer/maker redirect is in the test plan.
- **`/admin/login` caught by its own session gate (redirect loop).** *Mitigation:* the login route is placed outside the gated subtree (or explicitly excluded), so an unauthenticated admin can reach it. AC-2 + a loop-check in the test plan.
- **Invoice download wired to a non-existent endpoint (silent break / discarded PDF).** *Mitigation:* § Technical-notes verification step + Option E rebuttal + AC-7's two branches; the blob helper is the only download path, the generated `Promise<void>` file method is never used.
- **A KPI count crashes the overview when its read lacks a total.** *Mitigation:* A.2 — unavailable counts render "—" (defensive default), never throw; the tile still links to the real list. AC-4 pins the graceful placeholder.
- **A b/c forward-compat nav link ships as a live 404.** *Mitigation:* §C / Option H — those entries are disabled/pending or omitted; AC-3 greps for no live dead link.
- **A write call sneaks into the read harness.** *Mitigation:* AC-12 grep-for-absence of `refund`/`state`/`resolve`/`complete`/`retry`/`erase` and of any type-to-confirm; the `admin-client.ts` helper exports only the four read functions (+ the conditional invoice blob).
- **Vykání/tykání drift.** *Mitigation:* all admin copy is vykání behind `dashboard.admin.*` keys; the T8 gate fails CI on a missing key, so the catalog stays complete.
