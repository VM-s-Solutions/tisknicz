## Security (T-0178 is `security_touching`)
- **Audience gate:** the lookup lives on the admin host under `[Authorize]`; an anonymous call
  returning 401 is asserted, not assumed.
- **PII-read audit:** one `user.lookup` row on success only, targeting the **resolved user id** —
  the looked-up email never enters the audit row or the logs (asserted).
- **No enumeration concern:** this is an authenticated admin surface, so a truthful 404 is correct
  here; the uniform-failure rule applies to anonymous auth endpoints, not privileged reads.
- **The fix is a tightening, not a widening:** the erase screen previously accepted the operator's
  own typing as the identity. Scope stayed at lookup-only — no browse list — so PII exposure does
  not grow.

## Architecture
- Query-side only: `IAdminQueries` + a DTO + a one-file feature, mirroring the T-0111/T-0127
  precedents. No repository mutation, no new error code (`user.notFound` reused).
- `IgnoreQueryFilters` is deliberate and load-bearing: an erased account MUST resolve so the UI can
  distinguish it from "no such user" — that conflation was the ADM-M9 defect.
- Layering respected: the in-flight state list is duplicated in Infra rather than importing
  AppServices; the trade-off is written down in code and the test plan.

## Correctness
- T-0177's frontend filter is **removed**, so pagination now counts this order's rows only —
  keeping the client filter would have left the misleading page counts intact.
- Handler tests assert the filter actually reaches the query object, which is the thing that broke.
