## Security dimensions (this bundle is `security_touching`)
- **No open redirect:** both OAuth landing URLs are built from `PublicAppUrlsOptions.WebBaseUrl`,
  never from `Request.Host`/headers.
- **No PII in URLs:** the error redirect carries only the `BusinessErrorMessage` code; asserted by
  an integration test (no `@`, no `code=`, no `state=`).
- **No enumeration:** `resend-confirmation` dispatches the existing `SendEmailConfirmation`
  pipeline whose issuer owns uniform timing + per-email rate limiting and the already-confirmed
  silent no-op; the byte-identical response is asserted.
- **Rate limiting:** the endpoint inherits the class-level `"auth"` bucket (10/min per IP, T-0136);
  no `[DisableRateLimiting]`.
- **Idempotency grace is not a bypass:** it only reports success for a token the caller already
  holds AND whose user is genuinely confirmed; unconfirmed users and out-of-window replays still
  fail. `ConsumedAt` (not `IsRedeemable`) gates it, so an expired-never-consumed token cannot slip
  through.
- **Magic-link maker fallback is safe:** the backend does not burn the token on audience mismatch
  (existing `ConsumeMagicLink` behavior), so the retry is a legitimate second attempt, not a replay.

## Other dimensions
- **Architecture:** controller stays thin (dispatch + cookies + redirect); no business rule moved
  into the HTTP layer; the resend endpoint reuses the existing command rather than adding one.
- **Rules:** `CancellationToken` threaded, no PII logged (the log line carries `UserId` only),
  error codes from `BusinessErrorMessage`, zero `any` on the frontend, i18n in one block.
- **Tests:** 3 backend unit + 2 integration + 6 frontend; the StrictMode double-mount test would
  have caught the AUTH-M1 regression class directly.
- **Contract:** NSwag regenerated after restarting the dev hosts on this branch (the stale-host
  trap is recorded in the test plan so the next person doesn't repeat it).
