# Test plan — T-0112 (Maker payout queries — list + detail + order outbox-events)

## Scope under test
The maker-host read side of the money surface (`Web.Maker`, all
`[Authorize]` under the maker audience per ADR 0013):
- `GET /api/v1/payout-batches` — `GetMakerPayouts`: paged maker payout
  list, per-maker slice (`SUM(this maker's MakerPayoutAmountMinor)`, NEVER
  the cross-maker `PayoutBatch.TotalAmountMinor`), sorted
  `CompletedAt DESC, BatchNumber DESC`, empty page when the maker has none.
- `GET /api/v1/payout-batches/{batchId}` — `GetMakerPayoutDetail`: batch
  summary + this maker's per-order breakdown; **cross-maker OR unknown id
  returns the SAME 404 (no enumeration oracle)**.
- `GET /api/v1/orders/{orderId}/events` — `GetMakerOutboxEventsForOrder`:
  maker-scoped, read-only, **payload-free** outbox audit (event type +
  derived `OutboxDeliveryStatus` + timestamp only); cross-maker/unknown
  order → empty page (not 403, not an oracle).

IDOR shield enforced **twice** (handler resolves `makerId` from session;
projection re-filters). Read-only — no migration, no new error code, no
outbox event, no mutation.

## Preconditions
- Staging maker backend deployed from the bundle branch; maker-host NSwag
  client regenerated (the three endpoints + three responses + four DTOs +
  `OutboxDeliveryStatus`/`PayoutBatchState` enums).
- **Two maker accounts** (maker A, maker B) with maker-audience JWTs, plus
  one customer JWT (for the audience-rejection case) and a third maker
  with **zero** batches (empty-state + cross-maker-404 case).
- A **seeded `Completed` batch spanning ≥2 makers** (the critical IDOR
  case: one batch claims orders of both A and B), with per-maker Fee
  invoices + blobs rendered (so `FeeInvoiceId` populates), plus outbox
  events on A's and B's orders covering all three derived statuses
  (`Processed`, `Scheduled`, `Stalled`).
- Optionally one in-flight `Processing` batch (no `CompletedAt`) to verify
  nulls-last sort ordering.
- **Reduced test parallelism (known-env note, NOT a bundle defect):** run
  the payout-queries integration suite with
  `dotnet test --filter "MakerPayoutQueries" -- xUnit.MaxParallelThreads=2`
  to stay under the Testcontainers Postgres connection ceiling on busy
  boxes. Environment workaround only.

## Edge cases
- A batch row that exists but whose Fee invoices have NOT rendered yet
  (race) → `FeeInvoiceId == null`; the row still lists (T-0116 hides the
  download CTA). Verify null, not a 500.
- A maker with exactly one in-flight `Processing` batch and several
  `Completed` ones → the `Processing` row (null `CompletedAt`) sorts last;
  verify it appears at the bottom of page 1, not first.
- Events ordering: `CreatedAt DESC` (newest first) — verify stability
  across pages (no row repeats when a new event lands between page loads —
  acceptable drift, but no duplicate within a single page).
- `batchId` / `orderId` over the 40-char column width → 400 (MaxLength),
  not a DB error.
- A maker requesting their OWN order's events where that order has zero
  outbox rows → empty page (not 404) — distinguish "no events" from
  "not yours" (both empty, deliberately — no oracle).
