# Test plan — T-0125 (Debt-codification bundle)

Branch `chore/debt-codification-bundle`. This bundle MODIFIES the Gate 9 script
(`scripts/check-consistency.mjs`) itself — it adds two `hard:true` aggregate
rules (T8 i18n-parity, T9 unique-index→translator) plus three ride-alongs
(dispute-translator map, Q-0013 nav sweep, Q-0019 partial index). The test
plan therefore doubles as a **gate-regression procedure**: a future dev must be
able to re-prove that T8/T9 still bite and are not theater.

## Scope under test
- `scripts/check-consistency.mjs` — `ruleT8`, `ruleT9`, `T8_NO_KEY_REQUIRED`,
  the `hard` finding semantics in `finding()` / `writeBaseline()` / `main()`.
- `UniqueConstraintTranslator.cs` — new `ux_disputes_order_open` mapping.
- `OrderConfiguration.cs` (2 markers + `ix_orders_payout_unclaimed` partial),
  `InvoiceConfiguration.cs` (2 markers), `MakerConfiguration.cs` (1 marker).
- `OpenDisputeConcurrencyTests.cs` (integration).
- Frontend `/auth/login` → `/login` sweep (8 source refs).
- Migration `20260615083851_AddOrdersPayoutUnclaimedIndex`.

## Preconditions
- Node 20+ for the script cases (no npm deps).
- Testcontainers Postgres for the dispute integration test.
- `next build` available for Q-0013 route verification.
- Run the script cases from a **clean working tree** — the script reads the

## H. Gate-regression meta-test (prove the gates still bite)

A documented, repeatable procedure so a future dev can re-verify T8/T9 are not
theater. **Always run from a clean tree and revert after.**

1. **Baseline:** `node scripts/check-consistency.mjs` → exit 0, `145 tracked`.
2. **T8 bite:** add `public const string ZzTemp = "zz.temp";` to
   `BusinessErrorMessage.cs` (no cs-CZ key, not allowlisted). Run → **T8
   finding, exit 1**. Run `--update-baseline` then re-run → **still exit 1**
   (hard finding refuses to baseline; baseline still has **0** T8 rows).
   `git checkout -- BusinessErrorMessage.cs docs/audits/consistency-violations.md`.
3. **T9 bite:** append at the end of any
   `Configurations/*.cs` `Configure(...)`:
   `builder.HasIndex(x => x.Id).IsUnique().HasDatabaseName("zz_temp_idx");`
   (a column already keyed is fine — it is a syntactic probe, not a real
   migration). Run → **T9 finding, exit 1**. Add a `// no-translator: probe`
   line above it → exit 0. `git checkout -- <config>.cs`.
4. **Confirm restored:** `node scripts/check-consistency.mjs` → exit 0,
   `145 tracked`, working tree clean (`git status --short` shows no config /
   baseline / BEM changes).

If any step's exit code differs, the gate has regressed — investigate before
trusting a green CI run on this script.

## Open risks / notes
- **R1 (low):** the script reads the **live tree**, so any un-reverted temp
  violation (a stale `ix_temp_t9`-style probe) silently re-fires T9 on the next
  run. Mitigation: §H mandates `git status --short` clean as the final step;
  CI runs on a pristine checkout.
- **R2 (low):** T9's marker lookback binds a `// no-translator:` comment to the
  **next** `HasIndex` only while no code line intervenes. Correct behavior, but
  authors must keep the marker contiguous with its index — a property worth a
  reviewer eye (covered by TC-6 / §H step 3 vs. the artifact noted in §C).
- **R3 (informational):** `git diff master..branch` on the baseline shows +20
  T1 rows; these are **prior un-merged bundles**, not T-0125 (TC-2/TC-3). When
  this branch merges, master's baseline grows by those 20 legitimately.
