# Test plan — T-0126 (admin read follow-ups: invoice-PDF download + overview count endpoints)

## Scope under test
Three new read-only endpoints on `Web.Admin` (backend-only bundle, no migration / no
new error code / no new index):

1. **Invoice PDF download** — `GET /api/v1/admin-invoices/{invoiceId}/pdf`
   (controller-direct stream, `AdminInvoicesController`). Unscoped-by-id lookup via
   `IInvoiceRepository.GetByIdUnscopedReadOnlyAsync` — admin sees ANY invoice, no
   owner predicate (ADR 0013/0025). Mirrors T-0088/T-0112a streaming exactly, only
   the ownership lookup is swapped.
2. **Processing-payouts count** — `GET /api/v1/payout-batches/count?state=Processing`
   → `{ count }` (`GetProcessingPayoutsCount`, `IPayoutBatchRepository.CountByStateAsync`).
3. **Stalled-outbox count** — `GET /api/v1/outbox-events/stalled/count` → `{ count }`
   (`GetStalledOutboxCount`, `IOutboxConsumerRepository.CountStalledAsync`). Predicate:
   `ProcessedAt == null AND NextRetryAt == null AND LastErrorKind != None` — the
   load-bearing assertion of this ticket.

T-0118a's overview tiles ("Processing payouts" + stalled-outbox) and the faktury
"Stáhnout fakturu" button are **UNBLOCKED** by this ticket. The frontend re-enable
(wiring the tiles + un-disabling the button) is a **separate small T-0118a FE
follow-up, NOT in scope here** — this plan tests the backend endpoints only.

No admin UI consumes these yet, so manual cases execute against the staging admin
host via Swagger/curl with JWTs of each audience.

## Preconditions
- Staging backend deployed from `feat/admin-reads-followups`; the bundle migrations
  applied (PayoutBatches, OutboxEvent, Invoice render columns — all from prior
  tickets; **T-0126 adds no migration**).
- **Admin account** with a valid admin-audience JWT.
- **One customer JWT + one maker JWT + the ability to send an unauthenticated
  request** — for the 401 audience-rejection probes (ADR 0013: cross-host replay is
  rejected at authentication → 401, not 403).
- Seeded **invoices**: one fully-rendered (row present + `PdfBlobPath` set + a real
  blob in `BlobContainer.Invoices`); one row present but `PdfBlobPath == null` (render
  pipeline not finished); a known-unknown invoiceId that resolves to no row.
- Seeded **payout batches**: N in `Processing` (on distinct countries — the partial
  unique index `ux_payout_batches_open_per_country` allows only one open batch per
  country) + M in `Completed`.
- Seeded **outbox events** in mixed states (fixtures `MarkCreated` per the
  recurring-finding convention where Auditable; outbox rows are bookkeeping, not
  Auditable, so they enqueue directly): K stalled, ≥1 due/retrying, ≥1 fresh, ≥1
  processed, ≥1 acknowledged.

## Edge cases (challenge the all-pass)
- **Invoice number with a `"` or `\` char** — `EscapeFilenameForHeader` must escape it
  in the `Content-Disposition` (header-injection guard). Invoice numbers are
  platform-generated (`FV-CZ-NNNNNNNN`), so this is defensive; verify the escape runs
  anyway.
- **`If-None-Match: *`** on the invoice endpoint → 304 (the `*` wildcard branch in
  `ETagMatches`).
- **Multi-value `If-None-Match`** (comma-separated list including the live ETag) → 304;
  a list NOT containing it → 200 full stream.
- **Soft-deleted / anonymised invoice** — the Unscoped read uses
  `.IgnoreQueryFilters()`, so admin reconciliation can still stream a soft-deleted
  invoice's PDF. Confirm a soft-deleted invoice with a live blob streams 200 (NOT a
  filtered-out 404) — this is the explicit ADR 0025 admin-reconciliation behaviour.
- **`?state=` invalid enum value** (e.g. `?state=Banana`) on the payout count → model
  binding should reject (400), not silently default to Processing. Verify the binder
  behaviour matches the `[ProducesResponseType(400)]` declared on the action.
- **`?state` omitted entirely** → defaults to Processing (the action's default
  parameter), 200 with the Processing count.
- **Stalled row whose `LastErrorKind == None` but `NextRetryAt == null`** (a
  theoretical fresh-but-unscheduled row) → must NOT count (the `LastErrorKind != None`
  clause is what distinguishes a real stall from an un-dispatched fresh row). The
  fixture's fresh row covers the inverse; this edge confirms the AND is a true
  three-clause conjunction.
