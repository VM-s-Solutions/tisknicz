# T-0115 — Manual QA plan (customer review-submission UI)

Manual QA against the Vercel preview (no automated frontend harness at
MVP). **Vykání** copy throughout (customer surface). Pure presentation
slice — eligibility, rating math, and validation are backend-authoritative
(T-0100); this plan verifies render states + UX mirrors only.

## Preconditions
- Logged-in **customer** account (vykání surface) + a **maker** account
  to author a reply for the maker-reply-render case.
- A **seeded `Delivered` order** between this customer and the maker,
  with NO active review yet, reachable at `/objednavka/{id}`.
- A second order in `Shipped` (pre-`Delivered`, no review) for the
  no-block case; an order that ALREADY has a review for the
  already-reviewed read-only case.
- Backend on the bundle branch (T-0100 contract live; the
  `CustomerOrderDetail` payload carries the `canReview` / `review`
  signals — if absent, escalate as a T-0100 gap, NOT a T-0115 edit).
- **Reduced test parallelism note:** any backend integration fixtures
  shared with T-0100 (Testcontainers) run under the reduced-parallelism
  collection; the UI cases here are manual against the deployed preview.

## Eligibility / three render states — `/objednavka/{id}`
- [ ] **CTA appears only when Delivered/Completed + no review:** on the
      `Delivered`/`Completed` un-reviewed order, the review block renders
      below the message thread with the section heading + interactive star
      picker (1–5) + optional comment field — SSR (data-complete first
      paint, no client fetch flash) (AC-1).
- [ ] **No block on ineligible state:** on the `Shipped` order, NO review
      block, CTA, or empty placeholder appears at all (fully conditional
      on backend signals) (AC-7).
- [ ] **Existing review → read-only, never the form:** on the
      already-reviewed order, the read-only submitted-review block renders
      directly; the form is never shown (AC-6).

## Star input + submit gating
- [ ] **Star required (submit blocked without):** with no star picked the
      submit button is disabled; picking any star ∈ [1,5] enables it
      (AC-2).
- [ ] Star picker is keyboard-operable (`role="radiogroup"`, arrow keys +
      Enter/click select) with a focus-visible ring; the selected value
      is exposed via `aria-label` (AC-2).
- [ ] **Body optional + counter at 1000:** typing in the comment updates
      a live `{n}/1000` counter; input is capped at `maxLength={1000}`
      (UX mirror) (AC-4).
- [ ] Star-only submit: a chosen rating + EMPTY comment submits
      successfully (comment optional) (AC-3).

## Submit → read-only re-sync
- [ ] **Submit → read-only review shown:** on success `router.refresh()`
      runs; the form is GONE and the read-only block shows the chosen
      stars (display variant), the comment if any, and the Czech-formatted
      submission date. NO edit, delete, or re-submit control anywhere
      (AC-5).
- [ ] Re-entrancy: double-clicking submit (or two tabs) does not create a
      second review — the in-flight `useRef` guard blocks the second
      client click; a backend `reviewAlreadyExists` race renders inline
      (AC-8).

## Maker reply render
- [ ] **Maker reply rendered when present:** after the maker authors a
      reply, reloading the customer order page shows the reply beneath the
      customer's review under an "Odpověď výrobce" heading (read-only);
      absent reply → no reply panel (AC-6).

## Error paths (inline, no crash)
- [ ] Forced `reviewBodyTooLong` (crafted >1000 body past the mirror) →
      Czech parity copy renders inline; page stays usable, no raw error /
      crash (AC-4, AC-8).
- [ ] `reviewAlreadyExists` (another tab submitted first) and
      `reviewOrderNotDelivered` (state regression) → mapped Czech copy
      inline; page usable (AC-8).

## Responsive
- [ ] 375 / 768 / 1280: the review block, star picker, textarea + counter,
      and submit button render with no horizontal scroll at 375; tap
      targets reachable; star buttons focus-visible (AC-9).

## i18n
- [ ] All strings via `customer.review.*` keys (vykání) — no hardcoded
      Czech in the components (`review-form-client.tsx`,
      `submitted-review.tsx`, `star-rating.tsx`, the page branch).
- [ ] Error-code parity present for all five review codes
      (`reviewAlreadyExists`, `reviewOrderNotDelivered`,
      `reviewRatingOutOfRange`, `reviewBodyTooLong`, `reviewReplyTooLong`)
      — each resolves via the i18n parity gate (AC-9).
- [ ] Czech date format on the submitted review's `createdAt`
      (`9. 5. 2026` shape).

## Hygiene gate
- [ ] Zero `any`, zero unsafe `!`, props typed; zero `console.*`; zero
      unused imports / dead code.
- [ ] Server Components default; the ONLY `'use client'` is the
      `ReviewFormClient` island; no `useEffect` data fetching anywhere in
      the route folder.
- [ ] All data via `apiFetch` + the `reviews-client.ts` helper; route /
      component code never imports `lib/api-client/`; `lib/api-client/`
      untouched (consumed as regenerated by T-0100; pre-commit hook).
- [ ] `StarRating` is hand-built (no third-party star library); UI
      primitives from `components/ui/`; no inline `style={}` for layout;
      no arbitrary Tailwind values.
- [ ] `npm run lint` + `npm run build` + typecheck clean; `node
      scripts/check-consistency.mjs` exit 0 at the bundle baseline (138).
