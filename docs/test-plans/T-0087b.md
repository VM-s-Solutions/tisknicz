# Test plan — T-0087b (written by QA — maker implementer skipped the stub, deviation 6)

## Scope under test
Maker order detail at `/dashboard/maker/objednavky/[orderId]`: SSR
detail render (payout breakdown, timeline, shipping block, contact card,
attachments, invoice link), the state-aware action bar rendered purely
from `State + ShippingMethod` (accept / ship-with-confirm / handover),
the label blob download (NOT the generated `label()` — `Promise<void>`
discards the body), the shared T-0086b `OrderMessageThread` wired to the
maker trio (post / mark-read / ~30 s poll), the 404-not-403 IDOR stance,
and the two error-parity keys this ticket adds (`order.notFound`,
`order.invalidTransition`).

## Preconditions
- Vercel preview against the staging backend.
- **No NEW third-party manual steps** — Packeta sandbox (shipment +
  label) and Comgate sandbox (payment) setup are already listed on the
  shipping-pipeline / checkout-flow bundle plans; reuse those creds.
- Staging seeded with maker-owned orders covering the full matrix:
  Paid; Accepted × ZasilkovnaPickupPoint; Accepted × PersonalPickup;
  **Shipped with non-null `shippingCarrierRef`** + tracking URL (label
  download); Shipped via PersonalPickup (no carrier ref); Delivered;
  Completed; Cancelled. PendingPayment owned by the maker if reachable
  (see TC-16).
- One order with ≥ 2 attachments AND a non-null `invoicePdfUrl`
  (T-0088-generated); one order with neither.
- A thread with > 50 messages; the order's customer login available to
  post counterparty messages (badge round-trip).
- A second maker account (foreign-order 404) + a customer session
  (cross-audience).

## Edge cases
- **Throttled big-PDF label:** download a large label on a throttled
  network — button spinner holds for the duration; the blob path's
  120 s budget does not abort a normal-size file; no partial/corrupt
  PDF lands; double-click during flight does not fire a second request
  (pending-disable).
- Double-submit on "Odeslat": rapid double-click → second POST blocked
  by the disabled bar; if it slips, the backend state machine 409s and
  the alert handles it (no duplicate Packeta shipment).
- Draft message typed in the thread survives `router.refresh()` after
  accept/ship (client-island state preserved — T-0086b precedent).
- Two tabs polling the same thread: mark-read idempotency keeps the
  counter consistent; no flicker between 0 and N.
- `shippingCarrierTrackingUrl` null on a freshly Shipped personal-pickup
  order — shipping block renders without a dead link.
