# Test plan — T-0108 (UpdateCountryConfiguration — VAT / fee / providers / invoicing mode)

## Scope under test
Admin config-row mutation: `PUT /api/v1/country-configurations/{countryCode}`
on `Web.Admin`. Mutates the per-country control plane (ADR 0004) that
drives VAT math, platform-fee splits, default shipping price, invoicing
mode, and provider selection. Surfaces under test: VAT/fee/invoicing
update + before/after audit row, provider change behind the **retype
interlock** (`ConfirmedProviderCode` must equal the new value), unregistered
provider-code rejection (`country.providerNotRegistered`), in-flight order
**advisory** (`InFlightOrderCount` — WARN, never block), Silent-Success on
a true no-op (+ benign Q-0021 audit row), and admin-audience JWT enforcement.

No admin UI exists (T-0118 / downstream) — manual cases execute against the
staging admin host via Swagger/curl with an admin JWT.

## Preconditions
- Staging backend deployed from the admin-ops bundle branch; no migration
  ships for T-0108 (entity + columns + mutators already on master).
- **Admin account** with a valid admin-audience JWT (+ one customer and
  one maker JWT for the audience-rejection case).
- A seeded CZ `CountryConfiguration` row with known current values
  (`StandardVatRateBp`, `ReducedVatRateBp`, `PlatformFeeRateBp`,
  `DefaultShippingPriceMinor`, `InvoicingMode`, and all four
  `Default*Provider` codes — at MVP `comgate` / `packeta` / `ares` /
  `sendgrid`).
- A second registered payment-provider code to switch TO for the
  provider-change cases (the `IProviderRegistry` probe at MVP yields the
  keyed-service keys for payment + shipping; email/registry from the static
  `{ "sendgrid" }` / `{ "ares" }` fallback until T-0124). If only one
  payment provider is registered at MVP, the registered-alternate cases
  (TC-2/TC-3) use `packeta` for `DefaultShippingCarrier` as the changed
  provider field — record which field was exercised.
- 2 seeded CZ orders in in-flight states (`Paid` / `Accepted`) for the
  advisory case, each carrying a cached `PaymentProviderRef`.
- DB access to read back the `country_configurations` row + the
  `admin_audit_log` table.
- **Reduced-parallelism note:** integration tests run Testcontainers
  Postgres; run the bundle's integration suite with reduced parallelism
  (or the configured xUnit collection serialization) so the shared seeded
  CZ config row is not mutated concurrently across T-0108/T-0110/T-0111
  fixtures.

## Edge cases
- `reducedVatRateBp` exactly == `standardVatRateBp` → accepted (boundary;
  the rule is `<=`, only strictly-greater is rejected).
- `platformFeeRateBp` == 0 and == 10000 → accepted (inclusive bounds);
  10001 → 400.
- `defaultShippingPriceMinor` == 0 → accepted; negative → 400.
- Provider-code retype with trailing whitespace / different case — the
  registry probe is `OrdinalIgnoreCase` for the *registered-set* membership,
  but the retype-equality gate compares against the new command value:
  confirm whether `"Comgate"` vs `"comgate"` passes the retype (record actual
  — if the gate is case-sensitive a leniently-cased registered code could
  pass `providerNotRegistered` yet fail the mismatch; flag as a finding if
  the two checks disagree on casing).
- Multi-provider change in one PUT (payment AND shipping both changed): the
  retype must match the **payment** provider's new value (highest-stakes;
  US-admin-0006 AC-3 names the payment provider). Verify the gate keys off
  payment when payment changed.
- `reason` at exactly 2000 chars accepted; 2001 → 400.
- No-op PUT that ALSO carries a (matching, current) provider value with
  `confirmedProviderCode: null` → still Silent-Success (no provider field
  *changed*, so no retype required). Confirm the no-op path skips the gate.
