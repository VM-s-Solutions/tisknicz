# Test plan — T-0146 (reverse Zásilkovna shipping label — return-to-maker)

## Scope under test

Reverse (customer→maker) shipment creation on `IShippingCarrier` /
`PacketaShippingCarrier`; admin-triggered `GenerateReturnLabel.Command`
(category gate, idempotent re-run, payout-deduction recording); the
shared `GenerateLabelFunction` queue consumer discriminating
`shipping.generate.label` vs `shipping.generate.returnLabel`;
`FetchAndStoreReturnLabel` (T-0074 cache/carrier/cache-fill shape,
dispute-scoped blob path); the customer-host download endpoint
(`GET /api/v1/customer/files/disputes/{disputeId}/return-label`,
T-0075 cache-hit/cache-miss shape, IDOR-shielded); `MarkDisputeReturnReceivedByAdmin`
/ `MarkDisputeReturnReceivedByMaker` (AC-5); the `PayoutDeduction`
negative line item claimed by `CreatePayoutBatch` (Q-0037); and the
frontend customer download link + admin generate/mark-received actions.

## Manual / staging cases (no UI automation yet beyond the two islands shipped)

1. **AC-1 — generate.** Seed a `Delivered` order with an open
   `DamagedItem` dispute. As admin, POST
   `/api/v1/disputes/{disputeId}/return-label`. Assert: 200 with
   `carrierRef`/`trackingUrl`; `disputes.return_carrier_ref` /
   `return_tracking_url` set; customer's `/objednavka/{id}` now shows
   "Stáhnout vratkový štítek".
2. **AC-2 — cost never customer-facing.** After (1), inspect the
   customer's invoice/order total — unchanged. Run
   `POST /api/v1/admin/payouts/batches` (or wait for the weekly timer);
   assert the maker's payout total is reduced by
   `CountryConfiguration.DefaultShippingPriceMinor` and a
   `payout_deductions` row has `payout_batch_id` set to the new batch.
3. **AC-3 — cache-hit/miss.** First customer download after (1) is a
   live-Packeta fallback (check `GenerateLabelFunction` queue lag);
   subsequent downloads hit the blob (compare response latency /
   `Cache-Control: public, max-age=31536000, immutable`).
4. **AC-4 — transient retry.** Point `Packeta:BaseUrl` at a
   stub returning 503; admin retry of (1) surfaces
   `shipping.carrierUnavailable` (503) and is retryable once the stub
   recovers.
5. **AC-5 — mark received.** As the maker, POST
   `/api/v1/disputes/{disputeId}/return-label/mark-received`; assert
   `return_received_at`/`return_received_by` set and a second call 409s
   `dispute.return.alreadyReceived`. Repeat via the admin
   `.../mark-received` route on a fresh dispute to cover the
   "admin on the maker's behalf" path.
6. **AC-6 — category gate.** Seed disputes in `NotDelivered`,
   `CarrierReturned`, `CarrierFailed`, `Other`; the admin order-detail
   page must NOT render "Vygenerovat vratkový štítek" for any of them;
   a direct POST returns `dispute.return.categoryNotEligible` (400).
7. **AC-7 — IDOR.** As a different customer, GET
   `/api/v1/customer/files/disputes/{disputeId}/return-label` for a
   dispute you don't own → 404 (same shape as unknown id). Repeat for
   the maker `mark-received` route with a different maker's dispute id.
