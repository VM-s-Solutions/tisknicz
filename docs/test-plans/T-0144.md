# Test plan — T-0144 (Product fulfillment-type flag + checkout withdrawal-right copy)

## Scope under test

- `Product.FulfillmentType` (`MadeToOrder` default | `InStock`) on the domain entity, migration column default, `CreateProduct`/`UpdateProduct` commands + validators, and the field surfaced on `GetProductById` / `GetMyProductById` / catalog projection DTOs.
- Frontend: product-detail badge (`/produkt/[productId]`), maker create/edit form control (`/dashboard/maker/produkty`, defaulting to "Na zakázku"), and the checkout withdrawal-right notice (`/objednavka`) branching on `fulfillmentType`.
- Both notice variants are interim placeholder copy (T-0130 legal-placeholder-lock pattern) pending Q-0030.

## Preconditions

- Vercel preview against the staging backend, migration `AddProductFulfillmentType` applied.
- A maker account with at least one existing (pre-migration-equivalent) product to confirm the default backfill.
- Two staged products: one `MadeToOrder`, one `InStock` (via the maker edit form).

## Automated cases

### Backend (xUnit, `Makables.Tests`)

- `CreateProductHandlerTests.Validator_accepts_MadeToOrder_and_InStock` / `Validator_rejects_out_of_range_FulfillmentType` — `CreateProduct.Validator` enum-membership rule.
- `ProductMutationHandlerTests.Validator_accepts_MadeToOrder_and_InStock` / `Validator_rejects_out_of_range_FulfillmentType` — `UpdateProduct.Validator` enum-membership rule.
- `ProductFulfillmentTypeDefaultTests.ProductConfiguration_default_value_is_MadeToOrder` — EF model default value metadata pins `MadeToOrder` (AC-6).
- `ProductFulfillmentTypeDefaultTests.Product_created_without_explicit_FulfillmentType_round_trips_as_MadeToOrder` — end-to-end round trip through the SQLite test harness confirms a product created without an explicit fulfillment type persists and reloads as `MadeToOrder`.

### Frontend (Vitest)

- `produkt/__tests__/fulfillment-badge.test.tsx` — `ProductInfo` renders "Na zakázku" for `MadeToOrder` and "Skladem" for `InStock` (AC-3).
- `objednavka/__tests__/withdrawal-notice.test.tsx` — `WithdrawalNotice` renders the made-to-order copy vs. the in-stock copy per branch, and always shows the interim-copy label (AC-4/AC-5/AC-7).
- `objednavka/__tests__/checkout-a11y.test.tsx` (existing, extended) — `ProductDetail` fixture now includes `fulfillmentType` so the a11y suite continues to type-check and pass.

## Out of scope for this test plan

- Final legal wording review of either notice (gated behind Q-0030).
- Stock-quantity / inventory-count behavior (not introduced by this ticket).
- Retroactive notice display on past orders (no snapshot stored on `Order`).
