# Test plan — T-0101 (PayoutBatch entity + Order.PayoutBatchId + IPayoutBatchRepository + payout_batches migration)

## Scope under test
Entity slice of the payout bundle: `PayoutBatch` aggregate (born
`Processing`, immutable, set-once `AttachCsvBlobPath`), `Order.PayoutBatchId`
+ set-once `AssignToPayoutBatch`, `IPayoutBatchRepository`
(`AddAsync`, `GetByIdUnscopedAsync`, `GetOpenBatchAsync`, `GetByNumberAsync`),
the `payout_batches` migration (unique `(country_code, batch_number)` +
partial unique open-batch index + `orders`/`invoices` FK constraints),
batch-number format `VYP-CZ-YYYY-Www`, and the Q-0017 email-subject data-fix.

Pure domain + database PR — no controller, no contract change, no NSwag
regen. Behavioural ACs (claim, totals, exclusions) are T-0102a; integration
assertions ride T-0102a's PostgresHarness in the same PR.

- Branch built; both migrations applied to an empty `postgres:16-alpine`
  container (`FixSingleBraceEmailSubjects`/`FixEmailSubjectPlaceholders`
  leading, then `PayoutBatches`).
- No staging host endpoint exercises this slice directly — verification is
  via the automated suite + the T-0102a integration fixtures.

- Integration (rides T-0102a, same PR — `CreatePayoutBatchIntegrationTests` +
  `PostgresHarness`): migration apply + idempotent re-run, both unique-index

## Edge cases
- ISO-week year-boundary quirk (flagged in T-0102a Risk): a Jan 1–3 batch in
  ISO week 52/53 of the prior year is labelled with the calendar year
  (`VYP-CZ-2027-W53`). Uniqueness still holds; confirm the generator test
  documents this and it is not treated as a correctness defect at MVP.
- `AttachCsvBlobPath` with leading/trailing whitespace — trims before the
  set-once comparison; a same-value-after-trim retry must be idempotent.
- `BatchNumber` at exactly `MaxBatchNumberLength` (40) accepted; 41 rejected.
- Currency lower-case input (`czk`) → stored upper (`CZK`).

## Regression spot-checks
- Existing Customer-type `invoices` rows (all NULL `payout_batch_id`) survive
  the new FK constraint addition cleanly.
- Order state machine + existing order queries unaffected by the new nullable
  `payout_batch_id` column.
- Email rendering of the 16 previously-broken templates now expands
  `{{order_number}}` (no raw placeholder leaks to recipients).
