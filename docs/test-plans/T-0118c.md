# Test plan — T-0118c (admin ops + control-plane: outbox / country-config / payout / GDPR delete-user)

## Scope under test
The third and final admin-dashboard slice — the operator's **control-plane**
surfaces, including the **GDPR delete-user screen** (the only frontend driving
an irreversible hard-delete). Frontend-only (NO backend, NO NSwag regen;
consumes the existing `admin-api.v1.ts` retry/acknowledge, country-config PUT,
payout count/complete/csv, users erase, invoice pdf methods landed by
T-0108/0109/0103/0110/0126). Four surfaces, risk-ascending:

1. **Outbox** `/dashboard/admin/outbox` — stalled count + by-id retry /
   acknowledge.
2. **Country config** `/dashboard/admin/countries/{code}` — VAT/fee/provider
   edit + provider-change retype-the-new-code confirmation modal.
3. **Payout** `/dashboard/admin/vyplaty` — processing count + by-id
   mark-completed modal + operator CSV download.
4. **Delete-user** `/dashboard/admin/users` — type-the-exact-email +
   irreversibility banner + in-flight block (the critical path).

Plus the re-enabled admin invoice-PDF download (T-0126) on `/faktury` and the
two re-wired overview ops count tiles.

## Contract-gap callouts (NOT bugs — flagged backend follow-ups)
- **No outbox-event LIST read** on the admin contract — only the stalled
  `count`. The triage page renders the count + a by-id action surface.
- **No payout-batch LIST read** — only the processing `count` (the generated
  `payoutBatches()` is the CREATE POST, forbidden by A.3). The payout page
  renders the count + a by-id complete/CSV surface; no list ⇒ no `?page=`
  pagination yet.
- **No country-config GET** — only the PUT. The form has no server pre-fill;
  the operator enters the full editable set.
- **No user-lookup / per-user-order read** — only `erase`. The operator enters
  the user id + email manually; the in-flight-order block surfaces as the
  backend's post-call verdict (`user.cannotDeleteWithInFlightOrders`) rather
  than a pre-disabled button.

## Gate posture
- **T8 (i18n-parity) is LIVE and HARD-FAIL.** Every string this slice renders
  is keyed under `dashboard.admin.ops.*` in `frontend/src/lib/i18n/cs-CZ.ts`.
  Every backend error code consumed (outbox.* / country.* / payoutBatch.* /
  user.*) already has its parity key (landed by the backend tickets);
  `node scripts/check-consistency.mjs` exit 0 ⇒ T8 found no missing key.
- No NSwag regen, no `lib/api-client/` edit (read-only consumer, pre-commit
  hook). Admin tone = vykání throughout.

## Manual QA (Vercel preview, Playwright-style)

### 1. Outbox
- [ ] Page renders stalled count; count `null` → "—" + unavailable alert;
      count 0 → "fronta v pořádku" success alert.
- [ ] Retry with a valid id → success alert ("pokus č. N"); count refreshes.
- [ ] Retry on a processed row → `outbox.alreadyProcessed` clear alert ("už
      byla zpracována — není co opakovat"), NOT a silent success.
- [ ] Acknowledge button disabled until a non-empty reason; submit → success;
      re-ack of an acknowledged row resolves benignly (200).
- [ ] All mutation buttons disabled-while-pending.

### 2. Country config
- [ ] `/countries/CZ` renders the full editable form (no pre-fill — gap note
      visible); money/bp hints present.
- [ ] VAT/fee-only edit (no provider) → saves WITHOUT the modal; success alert.
      (Note: with no prior value to diff, any provided provider code opens the
      modal — verify the retype gate fires when a provider is entered.)
- [ ] Provider entered → save opens the retype-the-new-code modal; a mismatch
      surfaces `country.providerConfirmationMismatch`, nothing saved; an
      unregistered code surfaces `country.providerNotRegistered`.
- [ ] On a provider-change save with in-flight orders → the `inFlightOrderCount`
      advisory renders (informational, non-blocking).

### 3. Payout
- [ ] Page renders processing count; count states render coherently.
- [ ] Mark-completed modal: BankReference required (button disabled until set),
      PaymentDate optional; submit disabled-while-pending; success → settlement
      card (state "Vyplaceno", total via formatCzk, bank ref, date).
- [ ] `payoutBatch.notProcessing` / already-completed surface coherently
      (already-completed shows the benign info, not a false second completion).
- [ ] CSV download → `vyplaty-{batchNumber}.csv` (or id when number unknown)
      via the blob helper (NOT the generated `csv()`); failure → inline error
      alert. The CSV affordance exists ONLY on the admin surface.

### 4. Delete-user (critical path)
- [ ] Irreversibility banner ("Nevratné smazání … faktury zachovány dle GDPR
      čl. 17 odst. 3 písm. b)") prominent + ALWAYS visible on the confirm
      surface.
- [ ] Destructive button disabled by default; enables ONLY when the typed
      email EXACTLY matches the displayed email AND the reason is non-empty.
- [ ] Email mismatch keeps the button disabled (and a mismatch hint shows).
- [ ] Valid erase → terminal "uživatel byl trvale smazán" confirmation (NOT a
      refresh into a 404).
- [ ] Re-call / already-gone user → `user.notFound` rendered as "uživatel již
      byl smazán" (already deleted) — NOT a silent success.
- [ ] In-flight-order block → backend `user.cannotDeleteWithInFlightOrders`
      surfaces the inline "nejprve vyřešte rozpracované objednávky" reason.
- [ ] Erase button disabled-while-pending.
