# Test plan — T-0162 Customer registration "Jsem firma" + ARES autofill

Ticket: [T-0162](../tickets/T-0162-customer-company-registration.md)
Pure-logic TDD mandate applies (T-0067+): validator + handler tests are
committed red before the implementation commit.

## Automated — backend

### Register.Validator (pure logic — TDD)
- V-1 `CompanyRegistrationNumber = null` → valid (regression baseline).
- V-2 empty string → `validation.required`-class failure (treated as provided).
- V-3 length ≠ 8 (`"1234567"`, `"123456789"`) → length code.
- V-4 non-digits (`"1234567a"`, `"123 4567"`) → format code.
- V-5 valid 8-digit shape passes the validator (checksum is handler's).

### Register.Handler company branch (mock `ICompanyRegistryFactory`)
- H-1 null IČO → registry factory NEVER called; user persisted with NULL
  snapshot columns (regression).
- H-2 bad checksum (shape-valid) → validation failure BEFORE factory call
  (budget guard).
- H-3 active company → user persisted with snapshot (IČO, name, DIČ,
  FetchedAt from `CompanyRecord`); success response.
- H-4 `VatId = null` (neplátce) → snapshot persists with NULL DIČ.
- H-5 registry returns NotFound → failure passthrough, no user row.
- H-6 dissolved (`IsActiveInRegistry = false`) → customer-scoped dissolved
  code, no user row.
- H-7 registry returns Transient → failure passthrough, no user row.
- H-8 stale record (`IsStale = true`) → registration still succeeds.
- H-9 email-conflict pre-check still fires before the registry call is
  consumed by snapshot attach (ordering: conflict beats lookup errors).

### Integration (WebApplicationFactory, customer host)
Implemented as `Makables.IntegrationTests/Auth/RegisterCompanyIntegrationTests.cs`
on the Postgres harness (T-0063 CreateOrderTests pattern; registry factory
stubbed at DI). NOTE: the dev machine has no container runtime, so the
Testcontainers-backed suite runs in CI only — same as every other
`PostgresHarness` test (T-0160 precedent). Compile-verified locally.
- I-1 POST `/api/v1/auth/register` without the field → 200, row NULLs.
- I-2 POST with `companyRegistrationNumber` + stubbed registry → 200, row
  carries snapshot.
- I-3 POST with 7-digit IČO → 400, no user row.
