# Test plan — T-0118b (admin order detail + money/state action surfaces)

## Scope under test
The second admin-dashboard slice — the **order detail route**
(`/dashboard/admin/orders/[orderId]`) plus the three admin **write surfaces**
the order-cleanup backend bundle (T-0105/0106/0107) shipped endpoints for:
**refund** (money), **manual state change** (state machine), and **dispute
open + resolve**. Frontend-only (NO backend, NO NSwag regen; read-only consumer
of the `refund` / `state` / `dispute` / `resolve` / `auditLog` methods already
in `admin-api.v1.ts` from T-0105/0106/0107/0111). The slice owns **zero**
business rules: the refund gate, the manual-transition allow-list, and the
dispute parenthesis-state semantics all live in the backend; the UI renders
inputs and surfaces verdicts.

Three islands:
1. **`order-actions.tsx`** — refund MODAL + state-change MODAL, each with the
   money-grade disabled-button-while-pending idempotency lock (T-0087b
   precedent extended to money).
2. **`dispute-form.tsx`** — inline resolve form when `Disputed`, else inline
   open form (mutually exclusive by state).
3. **`page.tsx`** — Server Component: order header (degraded to list-row fields
   per the §C.2 composition gap) + audit-trail panel.

## Contract-gap callouts (NOT bugs — flagged backend follow-ups)
- **No admin order-detail DTO.** The header degrades to the `AdminOrderListItemDto`
  fields (T-0111). Line items, lifecycle timeline, payout/VAT breakdown,
  attachments, message thread are NOT in this slice — no admin read exposes
  them. A thin `GetAdminOrderDetail` follow-up is logged in
  `docs/questions/open.md`. **Verify the gap is labeled in-UI (degraded.title /
  degraded.body keys), not silent.**
- **No order-scoped audit endpoint.** The audit-trail panel reads the global
  `auditLog(...)` filtered to this order's id (§C.2). The audit *list* DTO omits
  before/after JSONB (T-0111 §G) — the side-by-side diff is US-admin-0015, out
  of scope. Verify the panel renders who/what/when only, no empty diff slot.
- **No dropdown-population endpoint** for the manual-transition allow-list
  (T-0107 deferred it). The UI offers all non-current `OrderState` values and
  lets the backend refuse — the allow-list is intentionally NOT client-side.

## Gate posture
- **T8 (i18n-parity) is LIVE and HARD-FAIL.** Every string this slice renders is
  keyed under `dashboard.admin.orderActions.*`; every surfaced backend code
  (`payment.refund.*` / `order.manualTransition.*` / `order.dispute.*`) must
  have its parity key. `node scripts/check-consistency.mjs` exit 0 ⇒ T8 found no
  missing key. **This is the biggest admin-UI string surface to date — confirm
  zero T8 violations on the new `orderActions.*` keys.**
- No NSwag regen, no `lib/api-client/` edit (pre-commit hook). Admin tone =
  vykání throughout.

## Preconditions
- **Admin (operator-audience) JWT** + a **non-admin (customer/maker) JWT** for
  the audience-replay negative.
- Seeded cross-tenant orders covering each state needed below: a `Paid`/`Shipped`
  order (refund happy + partial), a `Completed` order (post-payout-ack path), a
  `Disputed` order (resolve path), a non-Disputed order (open-dispute path), an
  order in a state from which a chosen target transition is **blocked** by
  `ManualOrderTransitionPolicy` (e.g. a transition the policy redirects to
  `useRefundOrder`).
- At least one already-refunded / terminal order to drive `invalidState`.
- A foreign / non-existent order id for the `notFound()` case.

## Risk-targeted edge cases (challenging the happy path)
- **Partial-refund double-submit on slow network** — the disabled-button lock is
  the only guard (no backend idempotency key). Throttle the network, double-click,
  assert exactly one POST. If a click slips, the second exceeds remaining →
  `amountExceedsRemaining` (bounded blast radius).
- **Post-payout ack false-negative** — Completed order: leave checkbox unchecked,
  confirm `ackValid` blocks the client submit AND that forcing the call yields
  `postPayoutAckRequired`. The UI gate must not be the only enforcement.
- **Optimistic-flip regression** — on every rejection assert the state badge did
  NOT change before `router.refresh()` (no client mirror).
- **Foreign-order audit leak** — confirm the audit panel for order A never renders
  order B's entries (the `auditLog` filter to this order id is correct).
