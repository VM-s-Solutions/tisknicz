# Test plan — T-0145 Dispute window + maker-response timer

## Scope under test

Two time-based rules layered onto the existing T-0106 Dispute/OrderMessage machinery:

1. **14-day open window** — `OpenCustomerDispute.Command` rejects with `order.dispute.windowExpired`
   when `Order.State == Delivered` and `now() > DeliveredAt + 14 days`. The other three openers
   (`OpenMakerDispute`, `OpenDispute` admin, `DisputeShipment` carrier) are untouched.
2. **7-day maker-response auto-escalation** — a new daily sweep (`DisputeAutoEscalationFunction` →
   `EscalateDispute.Command`) enqueues `dispute.autoEscalated.adminEmail` exactly once for an open,
   customer-sourced dispute past `CreatedAt + 7 days` with no maker reply since. Notification only —
   never resolves the dispute, never sanctions the maker.
3. Frontend: "Reklamovat" routes into the order-message thread (not a standalone dispute form); the
   thread gains a category selector + "Eskalovat na Makables" action gated on the 14-day window.

## Preconditions

- Vercel preview deploy (frontend) + the corresponding backend preview/staging API.
- A test customer account with at least one `Delivered` order (`Order.DeliveredAt` controllable via
  the admin manual-state tool or by waiting out the auto-deliver sweep in a seeded environment).
- Admin account with access to `ADMIN_NOTIFICATION_EMAIL` inbox (or the admin outbox-retry tooling
  from T-0109 to inspect parked/sent rows).
- `docker` available locally to run `Makables.IntegrationTests` (Testcontainers Postgres) — the
  automated cases below need it; this sandbox had no `docker` binary, so those suites are written
  but unexecuted here and must run in CI/a dev machine before merge sign-off.

## Edge cases

- Order in `Paid`/`Accepted`/`Shipped` (no `DeliveredAt`) — window guard never fires (AC-3, covered).
- Clock skew between the customer's browser and the backend — the frontend visibility check is
  presentational only; the backend's `order.dispute.windowExpired` is the sole authority and always
  wins on a mismatch.
- Dispute created exactly at the sweep's cutoff instant — repository predicate is `CreatedAt <
  asOf.AddDays(-7)` (strict), so a dispute created exactly 7 days before `asOf` is NOT yet a
  candidate; it becomes one on the next day's sweep. No dedicated boundary test at the repository
  level (mirrors T-0077's precedent of not unit-testing the exact cutoff instant beyond the handler
  tests above, which pin the seven-day constant via `Dispute.ResponseWindowDays`).
- Concurrent sweep runs / retried Function invocation — the `AutoEscalatedAt` stamp is the claim;
  `EscalateDispute.Handler` re-checks it after reloading the tracked entity (AC-8).
