# Test plan — T-0107 (ChangeOrderStateManually — admin escape hatch)

## Scope under test
`POST /api/v1/admin/orders/{orderId}/state` on `Web.Admin`: the strict
allow-list (`ManualOrderTransitionPolicy`), routing to semantic domain
methods (`MarkAsPaid` / `Cancel(Admin)` / `Accept` / `RevertAcceptance`
/ `MarkAsDelivered(AdminManual)`), blocked transitions naming the
sanctioned command, mandatory ≥10-char reason, same-state Silent
Success, admin audit row, admin-audience enforcement.

No admin UI (T-0118) — manual cases via Swagger/curl with an admin JWT.

## Preconditions
- Staging backend from the bundle branch (no migration in this ticket —
  `AdminManual = 3` is data-only).
- **Admin account** (admin JWT) + one customer and one maker JWT for the
  audience case.
- Seeded orders, one per state: PendingPayment WITH `PaymentProviderRef`,
  PendingPayment WITHOUT ref, Paid, Accepted, Shipped, Delivered,
  Completed, Cancelled, Refunded, Disputed (open one via T-0106 first).
- T-0105 + T-0106 executed first (bundle order; Disputed/Refunded seeds
  come from them).

## Edge cases
- `targetState` outside the enum (e.g. `"Banana"` / `99`) → 400
  `IsInEnum` validation, never a 500.
- Unknown order id → 404 `order.notFound`.
- TC-1 re-fired after success (now Paid → Paid) → Silent Success — the
  manual lost-webhook recovery is safely re-runnable.
- Reason of exactly 10 chars accepted (boundary).
