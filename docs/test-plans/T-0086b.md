# Test plan — T-0086b (stub — filled before bundle PR review)

## Scope under test
Customer order tracking detail at `/objednavka/[id]` for `Paid`+ states:
the state branch (PendingPayment regression gate), lifecycle timeline
(incl. cancelled branch), price breakdown reuse, tracking link,
authenticated attachment/invoice downloads, confirm-delivery transition,
and the shared `OrderMessageThread` (paging, post box, mark-read,
30 s visibility-aware polling — the platform's ONLY polling surface).

## Preconditions
- Vercel preview against the staging backend.
- Confirmed customer owning orders in: PendingPayment, Paid, Accepted,
  Shipped (with Zásilkovna tracking URL), Delivered, Cancelled.
- One order with 2 attachments + a generated invoice (T-0088); one with
  neither.
- One order thread with > 50 messages (for "load older") and unread
  maker messages.

## Automated cases
- None at MVP — no frontend test harness; this plan is the verification
  artifact (ticket §Test plan reference).

## Edge cases
- Thread SSR prefetch failure (backend blip): page still renders; thread
  starts empty and recovers on the first poll.
- Two tabs open on the same thread: both poll independently; mark-read
  idempotency keeps counters consistent.
- Slow download (large attachment on throttled network): button spinner
  holds; 120 s budget does not abort a normal-size file.

## Regression spot-checks
- PendingPayment pay CTA + attachment retry surface (T-0084b).
- `/objednavka/[id]/potvrzeni` poller unaffected (separate route).
- `/dashboard/zakaznik/objednavky` badge zeroes after a thread visit.
