# Test plan — T-0127 (Admin read gaps — country-config GET, admin order-detail, stalled-outbox + payout-batch LIST + 3 FE re-wires)

## Scope under test
Four thin, read-only `Web.Admin` query features (no command, no migration,
no new error code, no new index, no new outbox event) + three T-0118
frontend surfaces re-wired onto them:
- `GET /api/v1/country-configurations/{countryCode}` — current config,
  AsNoTracking, the EXACT `UpdateCountryConfiguration` Response field set
  (byte-round-trippable so the admin form pre-fills); 404 reuses
  `CountryConfigurationNotFound`.
- `GET /api/v1/admin-orders/{orderId}` — full privileged `AdminOrderDetailDto`
  (number, state, breakdown, country, maker, `customerEmail`, contact
  snapshot, timestamps), `Unscoped()` + `IgnoreQueryFilters()` + AsNoTracking,
  NO GDPR redaction; 404 reuses `OrderNotFound`.
- `GET /api/v1/admin-orders?customerUserId=X` — the per-user in-flight signal
  (a filtered admin-orders read; emptiness == "no in-flight").
- `GET /api/v1/outbox-events/stalled` (paged) — only the stalled set via the
  SHARED `IOutboxConsumerRepository.StalledPredicate` (byte-identical to
  `CountStalledAsync`).
- `GET /api/v1/payout-batches` (paged) — cross-maker `Unscoped()` batch list,
  NO bank-account field (CSV-only).

`security_touching: true` — the order-detail + payout LIST are `Unscoped()`
and must be reachable ONLY from `Web.Admin`; the privileged `customerEmail`
exposure on the order detail is deliberate (no redaction). The four reads
mirror the T-0111 `IAdminQueries` precedent. The FE re-wires are read-only
consumers of the regenerated admin client.

The load-bearing AC are **AC-4/AC-5 (T-0118c fence removal)** — the GET
pre-fill lets the provider retype modal gate on an ACTUAL provider-code diff
(VAT-only edits skip the modal) — and **AC-5 backend (the shared-predicate
guarantee)** — the stalled LIST and the count tile must agree on the exact
same set.

## Preconditions
- Admin Vercel preview deployed from `feat/admin-read-gaps`; backend deployed
  from the same branch. No migration, no new error codes, no i18n keys beyond
  the re-wire copy (info-note / no-prefill-note / in-flight-reason already
  keyed in cs-CZ).
- **Admin account** with a valid admin-audience JWT, PLUS one customer JWT and
  one maker JWT (the cross-audience rejection cases).
- **Seeded config:** a CZ `country_configuration` row with known
  VAT/fee/provider/invoicing-mode/shipping values (the pre-fill round-trip
  proof); confirm NO config row exists for an unknown code (e.g. `ZZ`) for the
  404 path.
- **Seeded orders (cross-tenant):** orders for customer A + customer B under
  makers X + Y; for the in-flight filter, customer A has ≥ 1 order in an
  in-flight state (`PendingPayment / Paid / Accepted / Shipped / Disputed`)
  and customer B has ONLY terminal orders (Delivered/Cancelled/Refunded).
- **Seeded outbox events (fixtures `MarkCreated`):** ≥ 2 STALLED
  (`ProcessedAt == null && NextRetryAt == null && LastErrorKind != None`),
  ≥ 1 PARKED/due (`NextRetryAt != null`), ≥ 1 ACKNOWLEDGED, ≥ 1 PROCESSED
  (`ProcessedAt != null`), ≥ 1 FRESH (never failed). Only the stalled subset
  may appear in the LIST and the count tile.
- **Seeded payout batches:** ≥ 1 Processing + ≥ 1 Completed, across ≥ 2
  makers (cross-maker `Unscoped()` proof).
- **Seeded users:** one user WITH an in-flight order (pre-disable case), one
  user WITHOUT (enabled case).
- DB access to confirm `totalCount` against the seeded population and to read
  SQL logs (AsNoTracking / two-round-trip / `Unscoped` / `IgnoreQueryFilters`
  assertions).
- **Reduced-parallelism note:** integration tests use Testcontainers Postgres;
  run with the configured xUnit collection serialization so the seeded
  population is stable while the list assertions read it.

## Edge cases
- **AC-5 fence-removal regression watch:** a VAT/fee-only edit MUST skip the
  modal (TC-3); if the modal still fires on a non-provider edit, the T-0118c
  AC-5 fence was NOT removed — FAIL, not a cosmetic nit.
- **Diff direction:** changing a provider then reverting it to the loaded
  value MUST clear the diff and skip the modal (TC-5) — the gate diffs vs the
  LOADED config, never "any provider field is non-empty".
- **404 → blank form** preserves the WARNING fence (TC-7): the safe default
  when there is nothing to pre-fill (silent-overwrite hazard returns).
- **Empty stalled / empty payout list** → 200 `PagedData` with
  `TotalCount == 0`, NEVER 404 (an empty admin list is success).
- **In-flight probe `unknown` (transient read failure)** → do NOT pre-disable
  (TC-18); the backend gate is authoritative. A false-block on a flaky probe
  would be a real defect.
- **`Disputed` is in the in-flight set** — a user with only a `Disputed` order
  is still pre-disabled (the states list is `PendingPayment / Paid / Accepted
  / Shipped / Disputed`).
- **Pagination stability** on the stalled + payout lists: rows sharing a
  `CreatedAt` keep stable boundaries via the `Id` tie-break (no row on both
  page 1 and 2).
- **`customerUserId` with a SQL-wildcard-looking input** — confirm the filter
  is parameterized (exact-match on the user id; no injection / match-all).
- **Soft-deleted / inactive order on the admin detail** — `IgnoreQueryFilters`
  surfaces it (the admin sees an erased order's header); an UNKNOWN id is the
  404 path, an INACTIVE id still resolves.

## Regression spot-checks
- The maker-scoped order list (T-0081) on `Web.Maker` still returns ONLY that
  maker's orders and still REDACTS `customerEmail` — the admin privileged
  exposure is host-isolated.
- The customer-scoped order detail (T-0082) on `Web.Customer` still bakes the
  owner predicate (no cross-tenant leakage); the new admin detail does not
  reuse the owner-scoped DTO.
- `GetStalledOutboxCount` / the overview count tile (T-0126) still returns the
  same number the new LIST's `totalCount` reports — the shared predicate makes
  them move together (TC-20). A drift here breaks BOTH.
- `UpdateCountryConfiguration` (PUT) still full-replaces and still gates the
  provider change server-side (`country.providerConfirmationMismatch` /
  `country.providerNotRegistered`) — the FE diff-modal is UX only; the backend
  re-validates regardless of what the form sent.
- `CreatePayoutBatch` (POST `/payout-batches`, T-0102a) still works — the new
  GET shares the route but the verb disambiguates; confirm POST is unaffected.
- `IOrderRepository.Unscoped()` / payout `Unscoped()` remain unreachable from
  `Web.Customer` / `Web.Maker` / `Web.Public` (Reviewer grep).
