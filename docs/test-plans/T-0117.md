# T-0117 — Manual QA plan (maker review-reply dashboard)

Manual QA against the Vercel preview (no automated frontend harness at
MVP; no backend change in T-0117). **Tykání** copy throughout (maker
surface, pending the tone open question — a flip is catalog-only). Pure
presentation: the backend (T-0100) recomputes the rating average; this
page renders + POSTs the single overwritable reply.

## Preconditions
- Logged-in **maker** account with received reviews (≥21 across ≥2 pages
  for the pagination case; at least one review WITH an existing reply and
  one WITHOUT for the form/edit split; at least one with a null comment).
- A **seeded `Delivered` order** between a customer and this maker, with a
  customer-submitted review (author it via the T-0115 customer flow or a
  seed).
- A **second maker** account with its own review for the cross-tenant /
  IDOR backstop spot-check (a foreign `reviewId` → backend 404, surfaced
  as the error alert).
- Backend on the bundle branch (T-0100 `GetMakerReceivedReviewsPaged` +
  `RespondToReview` + the maker rating-aggregate fields on the response
  envelope live).
- **Reduced test parallelism note:** backend integration fixtures shared
  with T-0100 (Testcontainers) run under the reduced-parallelism
  collection; the UI cases here are manual against the deployed preview.

## List render — `/dashboard/maker/recenze`
- [ ] **Received reviews list:** each card shows the rating as read-only
      stars (`Stars`, bp→0–5 conversion), the customer first name + order
      number, the comment (or a muted "bez komentáře" line when null), and
      the created date in Czech short format (AC-2).
- [ ] Reviews are most-recent-first (server sort `created_on DESC`,
      tiebreak `id DESC`) — verified by card order on the preview (AC-2).
- [ ] **Pagination:** `?page=2` → second page; prev/next round-trip
      reflects `PagedData` totals; `page=1` absent from canonical URLs;
      junk (`page=0`, `page=abc`) clamps to page 1 with no error page
      (AC-8).

## Reply form per review + overwrite
- [ ] **Reply form per review (no existing reply):** a review with no
      maker reply shows the reply form (`Textarea` ≤500 + submit) (AC-3).
- [ ] Submit a reply ≤500 on a no-reply review → POST `respondToReview`
      succeeds, `router.refresh()` runs, the card re-renders showing the
      new reply (no full navigation, no client optimistic mutation)
      (AC-4).
- [ ] **Overwrite existing reply:** a review WITH a reply renders the
      reply text + `MakerReplyAt` date + an edit affordance that opens the
      form pre-filled with the current reply; re-submitting a different
      reply OVERWRITES it (Q4 — one reply per review, single value, not
      appended) (AC-3, AC-4).
- [ ] Textarea mirrors `maxLength={500}` (UX); the backend
      `ReviewReplyTooLong` stays authoritative.

## Aggregate header (avg + count)
- [ ] **Aggregate header:** the page header shows the maker's average
      rating (stars + the 1-decimal numeric) and the review count read
      from the maker's rating fields on the response envelope
      (`RatingAverageBp` / `RatingCount`) — NOT averaged from the listed
      page (AC-6).
- [ ] Header invariant on page 2: navigate to `?page=2` — the header avg +
      count are IDENTICAL to page 1 (proves the header binds the
      authoritative maker field, not the visible window). **Grep proof:**
      no division / averaging over `items` in the header code (AC-6).

## Empty state
- [ ] **Empty state:** a maker with zero received reviews → the
      informational empty state (`dashboard.maker.reviews.empty.*`,
      "Zatím nemáš žádné recenze") — not an error, not a blank page; the
      header is hidden or shows "zatím bez hodnocení" per the empty key
      (AC-7).

## Customer-identity-absent (GDPR) assertion
- [ ] **No customer email / full name in the DOM:** inspect a review
      card's rendered HTML — only the customer **first name** + order
      number appear; NO email address and NO full/last name anywhere in
      the card, the page source, or the network payload
      (`MakerReceivedReviewDto` carries no customer identity beyond what
      the card shows — GDPR data-minimization, §C.7). Confirm the network
      response for `getMakerReviews` contains no `email` / `lastName` /
      `customerUserId` field.

## Error paths (inline, no crash)
- [ ] Reply POST fails (`ReviewReplyTooLong` via a forced >500 body,
      `NotFound` via a foreign/stale `reviewId`, network/5xx) → inline
      i18n-keyed `Alert` next to the form; submit re-enables; no card lost
      — the SSR list stays rendered (AC-5).
- [ ] List API 5xx/network → `Alert variant="error"` with i18n
      title/body + retry link; no blank page (AC-8).

## Responsive
- [ ] 375 / 768 / 1280: review cards stack with no horizontal scroll at
      375 (card list, not a grid table); the textarea + submit remain
      reachable at every breakpoint (AC-9).

## i18n
- [ ] All strings via `dashboard.maker.reviews.*` (+ `dashboard.maker.nav.reviews`)
      keys (tykání) — no hardcoded Czech in `page.tsx`, `review-card.tsx`,
      `reply-form.tsx`, `pagination.tsx`, `loading.tsx`, `error.tsx`.
- [ ] Czech-short dates via `lib/utils/dates.ts` for `createdAt` /
      `makerReplyAt`; plural-neutral review-count line.

## Hygiene gate
- [ ] Zero `any`, zero unsafe `!`, props typed; zero `console.*`; zero
      unused imports / dead code.
- [ ] Server Components default; the ONLY `'use client'` is the
      `reply-form.tsx` island; no `useEffect` data fetching anywhere in
      the route folder.
- [ ] All data via `apiFetch` + `reviews-client.ts` (`getMakerReviews` +
      `respondToReview` return `Result<…, ApiError>`); no generated-client
      method used for the POST (the error path needs `Result`); route code
      never imports `lib/api-client/`; `lib/api-client/` untouched (no
      regen in T-0117; pre-commit hook).
- [ ] No maker-facing flag / hide / moderation control; the customer
      review content is read-only DOM (only the reply textarea is
      interactive).
- [ ] `npm run lint` + `npm run build` + typecheck clean; `node
      scripts/check-consistency.mjs` exit 0 at the bundle baseline (138).
