# Test plan — T-0112a (Maker fee-invoice PDF download endpoint)

## Scope under test
`GET /api/v1/maker/files/invoices/{invoiceId}` on `Web.Maker`
`FilesController` (controller-direct blob stream per ADR 0014
§"Handler-free read paths", beside `GetShippingLabel`). Streams the
maker's own **Fee** invoice PDF. The lookup predicate IS the IDOR shield
(`i.Id == invoiceId && i.MakerId == makerId`, read-only `AsNoTracking`
mirror `GetForMakerReadOnlyAsync`). A cross-maker/unknown id, AND a
maker-owned **Customer** invoice via this Fee route, all return the SAME
`404 order.notFound` (no existence oracle). A null `PdfBlobPath` / blob
miss → `404 invoice.notYetRendered`. `Cache-Control: private, no-store` +
`Content-Disposition` + ETag/`If-None-Match` → 304 (recipient-PII policy
family, NOT the label's `public, immutable`). Maker-audience JWT enforced
per host (ADR 0013). No new error codes/migrations/i18n keys.

No maker UI exists yet (T-0116) — manual cases execute against the staging
maker host via Swagger/curl with a maker JWT.

## Preconditions
- Staging maker backend deployed from the bundle branch; maker-host NSwag
  client regenerated (the file-download method rides T-0112's regen).
- **Two maker accounts** (maker A, maker B) with maker-audience JWTs, plus
  one customer JWT and a maker-audience user with **no maker row** (for
  AC-5/AC-6).
- A **seeded `Completed` batch** with maker A's **Fee** invoice
  (`Type=Fee`, `PayoutBatchId` set, `MakerId=A`, `PdfBlobPath` set) and the
  blob bytes present in `BlobContainer.Invoices`. Also: maker A's per-order
  **Customer** invoice (`Type=Customer`, denormalised `MakerId=A`) for the
  wrong-type case, and maker A's Fee invoice with **null** `PdfBlobPath`
  for the not-yet-rendered case.
- **Reduced test parallelism (known-env note, NOT a bundle defect):** run
  the fee-invoice integration suite with
  `dotnet test --filter "MakerFeeInvoiceDownload" -- xUnit.MaxParallelThreads=2`
  to stay under the Testcontainers Postgres connection ceiling on busy
  boxes. Environment workaround only.

## Edge cases
- `If-None-Match: *` (wildcard) → 304 (the `ETagMatches` helper treats `*`
  as a match).
- Multiple comma-separated ETags in `If-None-Match` → match if any equals
  the blob ETag.
- `invoiceId` over the 40-char column width / blank → 404 (null-guard in
  the repo predicate), not a DB error.
- Range request header present → ignored (`enableRangeProcessing: false`);
  full body returned, no 206.
- A maker who owns BOTH a Fee and a Customer invoice with adjacent ids →
  the Fee route serves only the Fee one; the Customer id 404s (no
  cross-route bleed).
