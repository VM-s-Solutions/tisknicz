# Test plan — T-0087a (written by QA — maker implementer skipped the stub, deviation 6)

## Scope under test
Maker dashboard order list at `/dashboard/maker/objednavky`: SSR list
render via the forwarded maker-audience cookie (ADR 0024), the three
state tabs (Nové → `state=Paid` default / Ve výrobě → `state=Accepted` /
Vše → no state param) with exactly ONE list request per tab, URL-state
date/sort/pagination, per-row unread badges from the T-0079
`maker_unread_message_count` projection, the payout column (never gross,
never platform fee), the GDPR no-email surface, per-tab empty states,
and the error state.

## Preconditions
- Vercel preview against the staging backend.
- Verified maker with orders in mixed states: ≥ 1 Paid, ≥ 1 Accepted,
  ≥ 1 each of Shipped/Delivered/Cancelled (visible only under Vše),
  ≥ 1 row with `unreadMessageCount > 0`, ≥ 1 custom order with
  `productTitle = null`.
- A maker with ≥ 25 orders in a single tab for the pagination walk.
- A fresh verified maker with zero orders for the per-tab empty states.
- A logged-in customer session (cross-audience check).
- No new third-party manual steps — read-only list page.

## Edge cases
- `?tab=banana` (unknown tab slug) → falls back to Nové, no crash.
- `?page=99` beyond totalPages → empty page renders without crash; the
  per-tab empty copy must not mislead (no orders ≠ page out of range);
  pagination offers no further "next".
- `dateFrom = dateTo` (single-day range) returns that day's orders.
- `unreadMessageCount ≥ 10` — badge stays legible in both card and
  table layouts.
- Customer-audience session requesting the maker route → backend 401
  (ADR 0013 audience enforcement) → route-group auth guard behavior; no
  partial maker data renders.
