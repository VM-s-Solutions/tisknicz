# Test plan — T-0118a (admin shell + read surfaces: login, overview, all-orders, all-invoices, audit-log)

## Scope under test
The first admin-dashboard slice — **read-only + an auth gate**, frontend-only
(NO backend, NO NSwag regen; consumes the existing `admin-api.v1.ts`
`adminOrders` / `adminInvoices` / `auditLog` methods landed by
T-0105/0108/0109/0111). Five surfaces:

1. **Dedicated `/admin/login`** on the admin host (ADR 0013) — email+password
   only, no register / magic-link / OAuth; posts `login('admin', …)`.
2. **Admin shell** (`(admin)/dashboard/admin/layout.tsx`) — nav + header +
   logout + server-side admin-session gate (cookie presence).
3. **Overview** `/dashboard/admin` — deep-linking KPI tiles; order-by-state
   counts via `pageSize:1` count-probes off the all-orders read; ops tiles
   (payouts / outbox) render "—" + forward link (no fabricated 0).
4–5. **All-orders / all-invoices / audit-log** lists — SSR, `force-dynamic`,
   URL-state filters + pagination, mobile-cards / desktop-table.

This slice is the **verification harness** for slices b/c: their write effects
are asserted against these read lists. It must land complete and correct.

## Gate posture (behind-the-gate note)
- **T8 (i18n-parity) is LIVE and HARD-FAIL** — and it is the i18n-coverage
  mechanism for this slice. Every admin string is keyed under `dashboard.admin.*`
  in `frontend/src/lib/i18n/cs-CZ.ts`. A `BusinessErrorMessage` code with no
  cs-CZ key (and not allowlisted in `T8_NO_KEY_REQUIRED`) fails CI; a missing
  admin key is a build break, NOT a runtime `[missing key]`. `node
  scripts/check-consistency.mjs` exit 0 ⇒ T8 found no missing admin key, T9
  (unique-index translator parity) found no unregistered index. T8/T9 are
  NEVER baselined — they hard-fail in place.
- **T1–T7 baseline UNCHANGED by this slice.** The T-0118a delta
  (21c65e0→HEAD) touches `docs/audits/consistency-violations.md` zero times.
  See the audit note for the stale-local-master reconciliation.

## Preconditions
- **Vercel preview** deployed from the bundle branch; admin host reachable.
- **Admin account** with valid admin-audience credentials.
- One **customer** account + one **maker** account (cross-audience + no-flash).
- **Seeded cross-tenant data spanning ≥2 makers and ≥2 customers** (the admin
  surface is operator-wide / Unscoped):
  - Orders across states incl. **Paid, Accepted, Shipped, Disputed** (the four
    overview tiles) plus Completed/Cancelled; enough rows to force **>1 page**
    at the default page size.
  - Invoices of **both types** (Customer = 0, Fee = 1), multiple countries,
    spanning a date range; enough for **>1 page**.
  - **Admin audit rows** with varied `actionCode` (e.g. `order.refund`,
    `order.stateChange`), `targetEntity`, `adminUserId`; enough for >1 page.
- A second browser/profile (or incognito) to hold a customer/maker session
  while probing the admin host.

## Edge cases (a clean all-pass with none of these is suspect)
- **Phase-1 gate limitation (Watch-1):** the edge middleware AND the dashboard
  layout gate are **cookie-presence only** until T-0027 ships signature/audience
  validation. A forged/copied admin-named cookie value passes the FRONTEND gate;
  the real defense is the backend 401 on the SSR fetch (TC-6). Log T-0027 as the
  closing dependency.
- **customerEmail PII exposure:** appears ONLY on the admin host
  (operator-justified) — spot-check the maker order list still shows no customer
  email (regression).
- **Count-probe freshness:** seed a new Paid order, reload overview → Paid tile
  increments (force-dynamic, no stale cache).
- **Very long customerEmail / makerName:** `truncate` holds the 1280 grid; no
  overlap with the total column.
- **pageSize = `ADMIN_LIST_MAX_PAGE_SIZE` + 1** in URL → clamps to max, not 400.
- **Multi-value param** (`?state=Paid&state=Shipped`) → first value taken
  (`readString` array handling), no crash.
- **Disputed tile emphasis** flips off when the disputed count drops to 0.
- **Invoice `type` filter** ordinal vs label: UI sends `0`/`1`; filter control
  and row "type" label agree (Customer vs Fee).
- **Audit row with null/absent diff payload** still renders actionCode + target
  + timestamp without throwing.
